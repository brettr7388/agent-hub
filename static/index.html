Browser & passwords

Never type passwords into chat. Chat text is stored locally and sent to the AI provider. Log in yourself in the Pip browser if you want to use its separate profile. Full-access Pips inherit the browser and shell tools in your normal CLI configuration. A same-user full-tool Pip may access the credential store or browser sessions. For saved-login sites, use Private Pip for advice and browse/sign in yourself: Private Pip cannot automate Pip browser. Private Pip removes default integrations, but it is not an OS sandbox or an absolute vault barrier. Claude’s 1Password integration may also be available.

Use a separate Chrome profile without banking, health, or government accounts. Use another test browser profile when a Pip tests your work UI. Claude may pause before sending; a Pip can ask you to approve exact text with an approval card.

Help & Getting started

Start with Guide
  1. Open Guide and tap “Make me a Pip that…”.
  2. Review its proposal. Tap Create, Edit first, or No thanks.
  3. Try the Chef and Critic demo to see a group route a question and hand work to another Pip.

Guide’s greeting is free of model calls. The demo uses your signed-in CLI and may take longer than 30 seconds. Archive demo removes its chats from the list while keeping history.

Pips and your directory

Pips are your AI helpers. Open a chat’s settings to choose a colour, accessory and eyes, or use an emoji. Styles stay assigned across restarts. Pinned chats appear first, followed by recent activity and then names alphabetically. Search chats filters the sidebar as you type; press Enter or ⌘K for full search. When a list exceeds 12, Show all opens the directory for role filters, sorting and bulk archive. Larger directories show 60 per page.

Pip, group, team task

A Pip is a helper with its own instructions and model.

A group is a chat room with several Pips.

A team task asks Pips in a chat to work together and produces results you can compare or merge.

Use your phone

Open the phone guide below for the private link, QR code, and Home Screen steps. Keep this computer awake and Hub running.

Install or sign in to an engine

Follow Claude Code setup or Codex CLI setup. For Claude, run claude in Terminal and sign in. For Codex, run codex login. Restart Hub after signing in. Hub installs nothing for you.

Messages, groups, and team tasks

Enter sends; Shift+Enter adds a line. When a Pip is answering, new messages appear immediately and wait for its current turn. Use the separate Stop button to stop a response. /new starts a fresh session. The 👀 mark means work started. A group question gets one best-fit answer. Use @pip-name to ask one helper, or tap Ask everyone for a brief answer from each. If routing is ambiguous, Claude may use an isolated classifier with tools disabled; Codex uses the last responder if still in the group, otherwise the first Pip in the group. Hover a message for React and Reply. Right-click a bubble, or long-press it on a phone, for Copy and Retry. Reply can quote up to five messages; swipe right on a phone to add one. Reactions give feedback to the Pip who wrote the message: 👍 approves an approval request, 👎 declines it, ❤️ shows appreciation, and ❓ asks for an explanation of a proposal. 👍 and ❓ on an ordinary answer save the reaction without starting another turn. Approval cards show the exact proposed item; Approve or Don’t sends your answer to that Pip. Other decision cards may ask for confirmation.

A Pip can request a handoff only with a final standalone @@handoff target-name: task line outside quotes and code. Ordinary @name mentions do not delegate work. Handoffs run automatically in groups you create, with the full sender message and original request. Each chain allows at most three hops; the receiving Pip keeps its own permissions. A team task asks Pips to split work, compare answers, or run Research → Build → Review inside your chat. Use the composer’s + menu or the chat’s ▾ menu to start. Give helpers specific assignments to reduce overlap. Git changes stay separate until you review and merge; Hub does not commit them.

Schedules, approvals, and archived chats

Schedules repeat tasks while Hub and this computer are running. Missed or failed runs appear in the Pip chat and have a red dot in Schedules. Morning briefing and Weekly summary templates are editable before saving. Imported schedules are read-only.

Approvals shows drafts from an optional connected workspace. To use it, configure the approvals connector in Settings → Connections → Advanced first. Decision cards record your choice; an approval alone does not prove an external action happened. Pin a chat with its star. To restore an archived Pip, open All Pips, turn on Show hidden, then choose Unarchive. This works for linked and Hub-created Pips. Archived chats are separate: their files and history remain in local storage.

Pip settings, exports, and limits

Open a chat’s menu to edit a Pip’s name, instructions, model, working folder, Private Pip, and Draft only settings. Linked Pips let you change Private Pip and Draft only here; their other settings come from the source folder. Draft only produces chat prose drafts in a fresh restricted CLI session. It blocks all file writes, sends, posts, and team delegation. Incoming group handoffs keep these restrictions. Claude uses plan mode with tools restricted; Codex uses a read-only sandbox. Full access inherits the browser tools in your normal CLI configuration, including Claude in Chrome when available. The optional Pip browser is a separate profile; neither is the only browser a full-access Pip may reach. Private Pip runs with a separate restricted environment and cannot use Pip browser.

The chat menu exports that conversation as Markdown or JSON, including attachment names. Settings → Export everything downloads a ZIP of chats, Pips, and settings, excluding authentication files. Exports include your chat text. Review before sharing — we redact obvious secrets but can't catch everything. If a CLI reaches its usage limit, the message stays saved. Use Retry after the limit resets, or choose the other available engine.

Browser & passwords

Never paste passwords into chat. The optional Pip browser has a separate persistent profile on the host computer; tapping Open from your phone opens a window there. Private Pip and Draft only cannot use it. Full-access Pips also inherit browser tools from your normal CLI setup, including Claude in Chrome when available; neither browser is the only one they may access.

Saved logins use the host computer’s credential store. Each fill needs a fresh tap, shows the username before approval, targets fields without submitting, and works only on the exact HTTPS site or explicitly allowed subdomains (HTTP localhost or 127.0.0.1 with an exact port is allowed for local tests). After filling, click Sign in in the Pip’s login tab without reloading. A prompt-injected full-tool Pip running as your user may read the store directly. For saved-login sites, use a Private Pip for advice and browse/sign in yourself; Private Pip cannot automate Pip browser. Private Pip removes default integrations, but it is not an OS sandbox or an absolute vault barrier.

Use a separate browser profile without banking, health, or government accounts. A password manager such as 1Password may be another option for Claude.

Cost, privacy, and access

Hub uses your signed-in CLI accounts and their limits. Provider usage charges you enable still apply. Pips run on this computer, but prompts and files they read may be sent to the provider. Full access Pips use your normal CLI environment and available browser tools. Turn on Private Pip to skip global instructions and integrations. Private Pip does not sandbox the computer.

Lost the token? Stop Hub and run python3 hub.py --reset-token. Hub revokes existing sessions before saving the new token hash. If saving the auth file fails, the old token still works for a fresh login; rerun the reset command. If Hub is interrupted after revocation, existing sessions are logged out; rerun it to finish. Only the token hash is stored in data/auth.json. A busy port creates no first token: stop Hub, change port in config.json, restart, and open the matching local address (for example, port 4800 at http://127.0.0.1:4800).
